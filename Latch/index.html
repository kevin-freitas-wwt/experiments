Scroll-driven animation is the loud half of modern CSS and it only runs in one engine. The quiet half — the half that replaces the JavaScript you actually still write — shipped everywhere and nobody made a poster about it.

Every mechanism on this sheet was verified in headless Firefox and headless Chromium before it was drawn. Six of them. No script tag, no library, no build step, and no feature that one engine has and the other doesn't.

Fig. 1Anchored calloutsanchor-name · position-anchor · position-area · position-try-fallbacks

Tap a callout. Then resize the window narrow and tap again.

A callout has always been a measurement problem. You read a rectangle in script, write pixels into a style attribute, then re‑read it on resize, on scroll, on zoom, and on every layout shift you forgot about.

Anchor positioning replaces the measurement with a relationship. Each pin declares an anchor-name. Each note declares position-anchor and a position-area, and lists fallbacks for when the preferred side has no room. The browser resolves it at layout time, which is the only time the answer is ever correct.

The toggling is popovertarget. Focus, dismissal, escape, and the top layer are the browser's job now.

1 — Preferred side is inline-end. Squeeze the viewport and it flips, because position-try-fallbacks was told what to do next.

2 — Same stylesheet rule as every other note here. Only the anchor name differs.

3 — The note lives in the top layer, outside this section's stacking context, and still tracks its pin.

4 — Enter and exit are animated by @starting-style and transition-behavior: allow-discrete. See Fig. 5.

This is the pattern that kills the most script. A radio input is checked. An ancestor notices with :has() and sets a custom property. Everything downstream reads that property through a style container query and restyles itself.

No class toggling, no state variable, no event handler, and no component that has to be told twice. The switch at the top of this sheet is retyping the rack above and the whole document's spacing at the same time, and the two know nothing about each other.

The radio is also the accessibility story for free: it is a real form control, it is keyboard operable, and it announces itself.

An unregistered custom property is a string, and strings cannot be interpolated. That single fact is why animating a gradient, an angle, or a shadow spread used to mean a requestAnimationFrame loop writing values into inline styles.

@property gives the property a syntax, so the engine knows an <angle> from a <length> and can tween it on the compositor. Three declarations replace three animation libraries.

Registered properties also get an initial-value and an inheritance rule, which means they finally fail predictably instead of resolving to the empty string.

Fig. 4Scoped styles@scope · proximity · donut boundary

Inside the card. This paragraph is blue.

Inside the slot, which is the lower boundary. This paragraph is not blue, and no reset was written to stop it.

Back outside the slot, still inside the card. Blue again.

One rule, one boundary, no naming convention.

Thirty years of CSS architecture — BEM, CSS Modules, styled components, utility classes — exists to answer one question: where does this rule stop applying?

@scope ( .card ) to ( .card__slot ) answers it in the language itself. The rule applies from the root down and switches off at the boundary, and proximity beats specificity inside the scope, so nesting no longer needs escalating selector weight.

This is the least demoed and most consequential feature on the sheet. It does not animate, so nobody posts about it.

Fig. 5Discrete transitions@starting-style · transition-behavior · display

Animated both ways. The old problem: an element going to display: none had nothing to transition, so exit animations needed a script to delay the removal.

transition-behavior: allow-discrete lets display and overlay flip at the far end of the transition instead of the near end. @starting-style supplies the from‑state for an element that was not previously rendered.

Exclusive accordion, no script

Two <details> sharing a name behave as a radio group. Opening one closes the other.

And the second panel

This is the accordion component that has been rewritten in every framework, every year, since 2010.

Enter and exit animation for elements that come and go was the last honest reason to reach for a script on a static page. It is gone.

Both engines ship @starting-style and allow-discrete. Blink additionally animates overlay, which keeps a closing popover in the top layer while it fades; Gecko ignores that line and the transition still runs. That is what a real progressive enhancement looks like — one extra declaration, no branch.

:target is twenty years old and still the cheapest state machine on the web. The fragment is a string the browser already persists, syncs to history, and exposes to the address bar.

Paired with :has() the panels can style their own tab as current without any duplicated markup. The single-page-app version of this control ships about forty kilobytes.

The interesting divide is not Chrome against Firefox. It is that the features which make a nice video shipped in one engine, and the features which delete your code shipped in both. Only one of those got the attention.
