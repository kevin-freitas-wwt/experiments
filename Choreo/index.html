Scroll

For thirty years the browser asked a scripting language to do a job that belonged to the compositor.

01

Scroll is a timeline

The bar at the top of this window is not being updated by a listener. It is an animation whose clock is the document's own scroll position: animation-timeline: scroll( root block ). The browser runs it off the main thread, which is why it never stutters while the page is busy.1

Each paragraph in this column fades and rises on a view timeline instead: a clock that starts when the element enters the viewport and ends when it leaves. The element is its own scroll driver, so nothing needs to know where anything else is.

This used to be a library. Then it was an IntersectionObserver and forty lines of state. Now it is two declarations that ship in the browser.

1. Scroll-driven animations landed in Chromium 115 and are progressively shipping elsewhere. This footnote is a popover positioned with position-anchor — also no script.

02

Sticky knows it’s stuck

This heading is position: sticky, and it is also a container-type: scroll-state container. That means the stylesheet can ask whether it is currently pinned — @container scroll-state( stuck: top ) — and restyle it accordingly. Scroll slowly and watch it change weight as it catches.

Before this, “is the sticky thing stuck?” required a sentinel element, an observer, and a class toggle. It was the single most common reason a static page needed JavaScript at all.

The pattern generalises. A container can ask whether it is scrollable, whether it is snapped, whether there is content hidden above or below the fold. All of it queryable in CSS.

Which reframes the whole thing: these features are not new tricks for animators. They are the browser finally exposing the state it always had, so that the presentation layer can stop guessing.

scroll()

An anonymous timeline bound to the nearest scroll container, or the root.

view()

A timeline bound to one element’s trip across its scrollport.

animation-range

Which slice of that trip the animation actually occupies.

timeline-scope

Lets a named timeline reach elements outside the scroller. That thin bar above is driven by this strip.

anchor-name

Tethers one box to another, across stacking contexts, with fallback positions.

@view-transition

Animates between two whole documents. Declarative, cross‑page, no framework.

03

Anchors, not coordinates

Tooltips, footnotes, menus, callouts: every one of them used to mean measuring a rectangle in script and writing pixels into a style attribute. Then re-measuring on resize, on scroll, on zoom.

Anchor positioning replaces that with a relationship. This word — here — declares an anchor-name, and the note attaches itself to it with position-area, flipping to a fallback when it would leave the screen.2

The browser is doing the layout maths, at layout time, where it belongs. Nothing is measured twice.

Anchored to the word, not to a computed top and left. Resize the window and it stays honest.

2. position-try-fallbacks handles the case where the preferred side has no room, which is the part everyone’s hand-rolled implementation got wrong.

04

Across documents

The last piece is the one that still surprises people. A single at‑rule, @view-transition { navigation: auto }, and two separate HTML files will animate into each other on a normal link click. No router, no single-page app, no hydration.
